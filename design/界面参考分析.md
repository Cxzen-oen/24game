# 竞技对战类界面参考（逆向分析用）

> 说明：以下为公开成熟的实时竞技/答题类产品普遍采用的界面结构，按信息层级拆解，供逆向分析。
> 未附截图（检索服务当前不可用）。列出的每个“元素”都是这类产品的常见做法，可直接对照判断取舍。

## 一、主流对战类产品及其可参考点

| 产品 | 类型 | 最值得参考的点 |
|---|---|---|
| QuizUp（答题对战） | 双人实时答题 | 双方比分条并排、每题结束后展示“对/错+谁得分”的即时反馈 |
| Kahoot | 群体竞答 | 大屏出题、进度条、倒计时视觉放大 |
| 快问快答 / 一站到底 | 答题竞速 | 限时进度、抢答与淘汰的紧张感 |

| 皇室战争等卡牌对战 | 实时对战 | 顶部双方血条/能量、回合计时、底部出牌区 |
| 微信小游戏「跳一跳」「合成大西瓜」对战版 | 轻量对战 | 单屏集中、少弹窗、结果页清晰 |

## 二、通用界面分层（这些产品的共识结构）

### 1. 对战主屏：顶部是“状态”，中间是“题”，底部是“作答”
- **顶部状态条**（贯穿全屏，不用侧栏）：
  - 左：你（头像+分数）
  - 中：倒计时（大字、醒目，临近结束变色）
  - 右：对手（头像+分数）
  - 下方一条：当前题号 + 总题数（如 3/10）
- **中间题目区**：四张数字牌居中，字号大，留白足。
- **底部作答区**：算式输入框 + 可点选的数字/运算符键盘 + 提交。

> 关键结论：**比分、计时、进度都应放顶部状态条，而不是挤在左侧侧栏**。我上一版把双方比分放在左侧，是逻辑问题——对战时视线应集中在题目和顶部，不应左右扫。

### 2. 双方比分：并排对称，而非一上一下
- 你与对手的分数**左右并排**、等宽、居中对比，中间放计时。
- 常见做法：`[你 2]  ⏱02:18  [对手 1]`，三者一字排开。
- 答对时己方数字“跳动+变绿”，答错或对手得分时对方数字“跳动”，形成即时反馈。

### 3. 每题结束后的即时反馈（我上一版完全缺失）
- 每题提交后，短暂显示：✅ 正确 / ❌ 错误，以及“本轮谁先答对/谁得分”。
- 正确：自动进入下一题，约 0.5–1 秒过渡，不弹窗打断。
- 错误：保持当前题，提示可重试，但不跳题。

### 4. 倒计时与进度：视觉优先级最高
- 剩余时间用大号等宽数字，临近 10 秒变红并轻微放大/抖动。
- 定题赛用“已完成题数/总题数”进度条，而非只有数字。
- 进度条在顶部状态条下方，一眼可见。

### 5. 键盘与输入：不混在算式里
- 输入框只显示已输入算式（可编辑、可退格）。
- 键盘独立成一排/一块，放在输入框下方，数字与运算符分区着色：
  - 数字 0–9：中性色
  - 运算符 + − × ÷ 和括号：强调色
  - 退格、清空：次要色
- 键盘点击即插入到光标位置，不是简单追加到末尾。

### 6. 结果/结算页：独立页面，信息极简
- 顶部：胜 / 负 / 平 大字结论。
- 中间：本场数据（答对题数、用时、最快纪录是否刷新）。
- 底部：再来一局 / 返回大厅 两个主按钮。
- 不把结算信息塞在对战屏的角落。

## 三、我上一版的具体逻辑问题（对照上述共识）

| 问题 | 表现 | 应改为 |
|---|---|---|
| 比分放侧栏 | 双方比分在左侧竖排 | 顶部状态条左右并排 |
| 缺每题反馈 | 提交后无对/错即时提示 | 每题结束后短暂展示结果 |
| 计时不够醒目 | 计时在右上角小字 | 顶部居中大字，临近变红 |
| 进度无条 | 只有小方块 | 加进度条或清晰题号 |
| 键盘交互不完整 | 只追加到末尾 | 支持光标定位插入、退格 |
| 结算无独立页 | 结算说明挤在页脚 | 独立结果页 |

## 四、建议的最终信息架构（逆向后可按此重做）

```
对战主屏
├─ 顶部状态条（贯穿）
│   ├─ 你：头像 + 分数（左）
│   ├─ 倒计时（中，大字）
│   └─ 对手：头像 + 分数（右）
│   └─ 进度：题号 3/10 + 进度条（其下）
├─ 中间：四张数字牌（居中，大字）
├─ 作答反馈：✅正确 / ❌错误（每题结束短暂显示）
└─ 底部：算式输入框 + 数字/运算符键盘 + 提交

结果页（独立）
├─ 胜/负/平 大字
├─ 答对题数、用时、纪录
└─ 再来一局 / 返回大厅
```
