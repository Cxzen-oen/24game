# 24 点项目：小程序 vs H5 方案对比

> 汇报对象：导师 / 学院
> 日期：2026-11-05
> 目的：决定活动入口做微信小程序，还是先换服务器用 H5

## 一、结论（先看这一段）

**建议：先做 H5 + 迁移导师服务器，保证活动按期；小程序（web-view 套壳）作为二期，与 H5 共用同一套后端。**

理由：

1. **换服务器是两条路都要做的事**。小程序里的游戏仍然是现在的 H5，服务器、数据库、域名、HTTPS 一个都少不了；先迁移不会浪费。
2. H5 上线快，不依赖审核；域名和 HTTPS 到位后，文章“阅读原文”、二维码、学校官网都能直接放。
3. 小程序的价值主要在**微信文章内一键进入、微信身份、复访入口**；如果活动在 3～5 周后，且学校主体、公众号、备案域名都齐备，可以同步启动 B 方案，不影响 H5 先上线。

**不建议：原生小程序重写。** 为一个活动重写全部前端，工作量 1～2 周，还要再走一遍审核，收益不如 web-view。

## 二、项目目标与现状

### 目标

- 在文章里放一个入口，读者点击后能进入 24 点游戏；
- 能持续玩、能记录成绩、能看排行榜；
- 学校/学院主导，偏团队活动，不是商业游戏。

### 现状

- H5 已完成：游客试玩、注册登录、A/B × L1/L2 四个排行榜、服务端判题与计时、刷新恢复、每日备份；
- 当前跑在一台自用 2C2G 服务器上，原生 systemd + PostgreSQL，适合小规模测试；
- 小程序还没做；学校主体、公众号、备案域名情况待确认。

## 三、三种方案对比

| 维度 | A. H5 + 换服务器 | B. web-view 小程序 + H5 | C. 原生小程序（备选） |
|---|---|---|---|
| 用户入口 | 文章“阅读原文”、二维码、学校官网/群链接 | 公众号文章内小程序卡片，一键进入 | 同 B |
| 微信内体验 | 普通网页，需登录或游客 | 小程序壳，微信身份，最近使用可复访 | 最原生，但开发量最大 |
| 开发量 | 0（现有 H5） | 小程序壳 + 登录桥，约 3～5 天 | 前端重写 1～2 周+ |
| 上线周期 | 1～3 天（域名/HTTPS 另算） | 3～5 周（备案+审核） | 4～6 周+ |
| 必要资质 | 域名 + HTTPS；有备案更稳 | 非个人主体 + 小程序备案 + 业务域名 + 公众号（插卡片） | 同 B，另加类目/软著要求 |
| 登录/身份 | 用户名密码或游客；服务号可网页授权 | wx.login 静默登录，需做一次性 ticket 桥 | 同 B |
| 持续玩/复访 | 服务端存档；浏览器历史/浮层 | 服务端存档 + 微信“最近使用” | 同 B |
| 审核风险 | 无 | 中：纯 web-view 可能被判无实质内容/类目不符 | 中高：类目、游戏判定 |
| 服务器 | 需要（建议 4C8G 起） | 同样需要，B 不替代服务器 | 同样需要 |
| 成本 | 服务器 + 域名 | 服务器 + 域名 + 小程序认证约 300 元/年 | 同 B + 开发人力 |
| 适用场景 | 活动近、入口不限微信、先跑起来 | 公众号为主、要一键进入、能等 3～5 周 | 长期产品、愿意重写 |

## 四、关键差异，用大白话说

### 1. 文章里怎么点

- **H5**：公众号正文不能放普通外链，只能放文末“阅读原文”，或者放二维码让读者长按识别；学校官网、微信群、邮件里可以直接放链接。
- **小程序**：公众号关联小程序后，文章里可以插入小程序卡片，读者点一下直接进；这是 B 方案最大的体验优势。

### 2. 用户是谁

- **H5**：游客靠浏览器本地标识，换设备就丢；要跨设备/上榜得注册登录。
- **小程序**：wx.login 拿到微信身份，点进来就能识别同一个人；但 web-view 里不能直接 wx.login，需要后端做一次性 ticket 桥（约 2～3 天）。

### 3. 能不能“持续玩”

两种都能。游戏状态存在服务端，刷新/重进能恢复；区别是小程序有“最近使用/我的小程序”，复访更方便，H5 更依赖收藏/历史。

### 4. 风险在哪

- **H5 的风险**：公众号文章里入口不够顺；没有小程序卡片；微信内分享/打开受平台规则影响。
- **小程序的风险**：备案和审核时间不可控；纯 web-view 容易被判“无实质内容”；类目可能被判定为游戏。规避方式是加原生首页/规则/排行榜/关于页，web-view 只承载玩法。

## 五、时间与成本

| 项目 | A. H5 + 换服务器 | B. web-view 小程序 |
|---|---|---|
| 服务器迁移 | 1～2 天 | 1～2 天（同样要做） |
| 域名/HTTPS | 有域名 1～3 天；新备案 7～20 个工作日 | 同左 |
| 小程序注册/认证 | — | 1～3 个工作日 |
| 小程序备案 | — | 1～22 个工作日 |
| 开发 | 0 | 壳 + 登录桥 3～5 天 |
| 审核 | — | 1～7 天 |
| **总计** | **约 1 周**（域名现成） | **约 3～5 周** |
| 额外费用 | 服务器、域名 | 小程序认证约 300 元/年 |

> 如果活动在两周内开始，B 方案基本赶不上；如果在一个月以后，B 可以并行做。

## 六、推荐路线

### 第一步：本周先把 H5 迁到导师服务器

- 装 Java 21 + PostgreSQL，迁 jar、数据库、env、systemd；
- 配域名和 HTTPS（有域名的话）；
- 按活动规模选配置：500 人同时在线建议 4C8G 起，先压测再定；
- 这一步两条路线都要做，不浪费。

### 第二步：同步评估 B 方案

只要满足下面三条，就可以启动：

1. 学校/学院能提供**非个人主体**和认证材料；
2. 有**已备案域名**，能配 HTTPS 和业务域名；
3. 活动在 **3～5 周后**，能接受审核时间。

启动后做：小程序壳 + 业务域名 + 登录 ticket 桥 + 提审；H5 继续作为兜底入口。

### 第三步：文章发布

- 有公众号且已关联小程序：文章插小程序卡片；
- 没有：先用“阅读原文”/二维码放 H5，等小程序上线再补卡片。

## 七、需要导师拍板的 4 件事

1. **活动时间**：两周内、一个月后，还是本学期内？
2. **入口要求**：必须在公众号文章正文里一键进入，还是“阅读原文”/二维码也能接受？
3. **主体与资料**：学校/学院能否提供非个人主体、认证、公众号、备案域名？
4. **规模与预算**：预计多少人同时在线？服务器用现有 2C2G，还是换 4C8G/8C16G？

## 八、一句话总结

**换服务器是必做的，小程序是加分项，不是替代项。**
活动近、资料不齐，就先 H5；活动还有一个月、公众号是主阵地，就 H5 先上线、B 方案并行推进。

---

附：术语

- **H5**：手机浏览器打开的网页，不需要安装。
- **web-view**：小程序里嵌入网页的组件，只有非个人主体可用。
- **小程序备案**：上线前必须完成的工信部备案，不是域名 ICP 备案。
- **业务域名**：小程序允许嵌入的网页域名，必须 HTTPS、已备案，并上传校验文件。
