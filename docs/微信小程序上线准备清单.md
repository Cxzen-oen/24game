# 微信小程序上线准备清单（24 点）

> 结论先说：以现在的代码基础，最稳的是 **企业主体 + 原生小程序（工具/教育类目）+ 现有 Spring Boot 后端**，不做 web-view、不走小游戏。这样不需要游戏版号，周期约 3～5 周，现有账号、对局、排行榜全部可以复用。
> 本文把「资质、备案、域名、登录改造、前端改造、合规、提审」按先后顺序列清楚。

## 0. 先做路线选择

| 方案 | 做法 | 工作量 | 资质门槛 | 风险 |
|---|---|---|---|---|
| **A. 原生小程序（推荐）** | WXML/WXSS/JS 或 Taro 重写前端，调现有 HTTPS API | 前端 1～2 周，后端 2～3 天 | 小程序备案 + 域名 ICP 备案 | 类目若被判定为“游戏”，会被要求改走小游戏 |
| B. web-view 套壳 | 小程序里放一个 web-view 指向现有网页 | 2～3 天 | **仅非个人主体**，需配置业务域名 | 个人主体不可用；审核易判“无实质内容/类目不符”；微信登录、分享受限 |
| C. 小游戏 | Canvas 引擎重写（Cocos/Laya/原生 Canvas） | 3～6 周 | 游戏类目 + 软著；IAA 需小游戏备案，IAP 需版号 | 周期最长，IAP 版号按“月”计 |

**建议 A**：24 点本质是数学心算练习，按“工具/教育”申报，不做虚拟支付、不做对战下注、不做抽奖，避免触发游戏类目。

## 1. 主体与小程序账号

### 1.1 个人主体 vs 企业主体

| 能力 | 个人主体 | 企业/组织主体 |
|---|---|---|
| 注册小程序 | 可以 | 可以 |
| 微信登录（openid） | 可以 | 可以 |
| web-view 内嵌网页 | **不可以** | 可以（需业务域名校验） |
| 微信支付 | **不可以** | 可以（需商户号） |
| 手机号快速验证 | **不可以**（要求非个人且已认证） | 可以，0.03 元/次，含 1000 次体验额度 |
| 可选类目 | 较少（工具、教育服务、生活服务等） | 全量类目 |
| 微信认证 | 一般不需要 | 约 300 元/年（以平台实际收费为准） |

如果只是自己玩/小范围分享，个人主体也能上线；但要做手机号登录、支付、web-view，必须企业主体。

### 1.2 注册前准备的材料

- 一个**没有注册过微信公众平台**的邮箱；
- 管理员本人微信、手机号、身份证；
- 企业：营业执照、法人信息、对公账户（微信认证打款验证）；
- 小程序名称（全平台唯一，建议“24点心算练习”这类工具化命名，避免“游戏/对战/竞技”字样）；
- 头像（建议 144×144 以上）、简介、服务类目；
- 一台已备案的服务器与域名（见第 3 节）。

注册入口：<https://mp.weixin.qq.com>，注册后拿到 **AppID**；AppSecret 在「开发管理 → 开发设置」生成，**只能放服务端**。

## 2. 两个备案，别混淆

### 2.1 小程序备案（工信部，必须）

- 2023-09-04 起新增小程序开放备案入口；**未完成备案不能发布上线**。
- 入口：小程序后台「设置 → 小程序备案 → 去备案」。
- 材料：主体证件、主体负责人证件、小程序负责人（管理员）信息、真实性核验（人脸/手持证件）、涉及前置审批的类目另交批文。
- 流程与时效：平台初审 1～2 个工作日 → 工信部短信核验（12381，24 小时内完成）→ 省通信管理局 1～20 个工作日。
- 通过后下发小程序备案号，发布后自动展示在小程序资料页。

> 小程序备案 ≠ 域名 ICP 备案，两个都要做。

### 2.2 域名 ICP 备案（服务器侧，必须）

- 小程序 wx.request 只能请求**已配置的 HTTPS 域名**；域名必须完成 **ICP 备案**。
- 域名不能是 IP、不能带端口、不能用 localhost（微信后台会直接报错）。
- 大陆服务器 + 大陆备案接入商最顺；**如果确定做小程序，前面文档里“香港服务器免备案”的选项就不适用了**——没有备案域名，小程序无法配置请求域名。
- 备案周期通常 7～20 个工作日，建议最先启动。

## 3. 域名、HTTPS 与服务器

| 项 | 要求 |
|---|---|
| 域名 | 已实名、已 ICP 备案；建议单独子域，如 api.example.com |
| 协议 | 必须 HTTPS，TLS 1.2+，证书由受信任 CA 签发（Caddy 自动签发即可） |
| 端口 | 不能带端口，标准 443 |
| 服务器 | 大陆 2C4G 起；数据库仍不暴露公网 |
| 小程序后台配置 | 「开发管理 → 开发设置 → 服务器域名 → request 合法域名」填 https://api.example.com |
| 业务域名 | 只有用 web-view 才需要；原生小程序不需要 |

注意：api.weixin.qq.com 被平台禁止配置为小程序请求域名，**AppSecret 和微信接口调用必须放服务端**。

## 4. 微信登录：后端要改什么

现有账号是“用户名 + 密码 + JWT + HttpOnly Refresh Cookie”。小程序没有可靠的浏览器 Cookie 机制，需要加一套**微信登录 + Body/Header 令牌模式**。

### 4.1 登录流程

~~~text
小程序 wx.login()
   │ code（5 分钟有效、一次性）
   ▼
POST /api/auth/wechat/login { code, guestId? }
   │ 服务端用 AppID + AppSecret 调 jscode2session
   ▼
微信返回 openid / unionid / session_key
   │
   ├─ 已有 account_identities(provider=WECHAT, subject=openid) → 取账号
   └─ 没有 → 建账号（默认昵称“玩家xxxx”）并绑定 openid
   ▼
返回 accessToken + refreshToken（JSON body）+ 账号信息
~~~

### 4.2 数据库与接口改造

新增一张表（V3 迁移）：

~~~sql
CREATE TABLE account_identities (
    id          uuid PRIMARY KEY,
    account_id  uuid NOT NULL REFERENCES accounts(id) ON DELETE CASCADE,
    provider    text NOT NULL CHECK (provider IN ('WECHAT', 'PHONE')),
    subject     text NOT NULL,          -- openid / 手机号
    created_at  timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT uq_identity UNIQUE (provider, subject)
);
~~~

新增/调整接口：

| 接口 | 说明 |
|---|---|
| POST /api/auth/wechat/login | code 换 openid，登录或建号，返回令牌 |
| POST /api/auth/refresh | 增加从 X-Refresh-Token 头读取（小程序无 Cookie） |
| POST /api/auth/logout | 同上，支持 Header 令牌 |
| GET /api/auth/me | 不变 |
| POST /api/auth/wechat/bind | 可选：把微信身份绑到已有用户名账号 |

服务端需要：

- 缓存微信 access_token（2 小时有效，提前 5 分钟刷新），用于内容安全等接口；
- **AppSecret 只放环境变量**，绝不进小程序代码；
- 如果以后要网页端和小程序同一账号，需要微信开放平台绑定后拿 unionid，否则 openid 只在小程序内唯一。

### 4.3 游客与资料

- 小程序本地 wx.setStorageSync('guestId')，登录时带上，继续复用现有“游客成绩并入账号”逻辑。
- 头像昵称：不再用 getUserInfo，用 button open-type="chooseAvatar" + input type="nickname"；昵称提交前服务端做 **msgSecCheck 内容安全检测**。
- 首版可以不存头像（用昵称首字生成圆形头像），减少图片内容安全与存储。

## 5. 前端要改什么

现有前端是浏览器 DOM 应用，**不能直接跑在小程序里**（没有 DOM/BOM）。可复用的是纯逻辑：merge.ts 的合并/撤销/表达式、API 数据结构、服务端规则。

### 5.1 两种做法

| 做法 | 说明 | 适合 |
|---|---|---|
| 原生小程序 | WXML/WXSS/JS，重写页面 | 页面少、追求稳定和审核通过率 |
| Taro / uni-app | React/Vue 语法编译到小程序 | 团队熟悉 React/Vue，或同时要 H5 |

24 点只有 6 个页面左右，原生重写更可控。

### 5.2 页面清单

1. 首页：模式 A/B、难度 L1/L2、我的最佳、开始；
2. 作答：牌面、算符、表达式、撤销、提交、跳题、退出、倒计时；
3. 结算：成绩、新纪录、再来一局、看榜单；
4. 排行榜：A/B × L1/L2、分页、我的排名；
5. 我的：昵称/头像、历史、退出登录；
6. 协议：用户协议、隐私政策（审核必查）。

### 5.3 技术注意点

- 请求封装：wx.request + Bearer；401 时用存储的 refreshToken 刷新并重放一次；
- 令牌存 wx.setStorageSync（access/refresh），不要依赖 Cookie；
- 计时：服务端时间为准；onHide 停止本地定时器，onShow 重新拉取对局对齐，避免小程序后台挂起导致计时漂移；
- 分享：onShareAppMessage 分享战绩/榜单；
- 代码包：主包 2MB 限制，图标用字体或内联 SVG 需转 base64 控制体积；
- 适配：rpx + 安全区，真机测试 iOS/Android 各一台。

## 6. 合规、隐私与内容安全

- **隐私保护指引**：小程序后台填写收集的信息（openid、昵称、设备信息、日志），并提供可访问的隐私政策页面；
- **用户协议/隐私政策**：小程序内要有入口，审核会点；
- **隐私接口声明**：使用 chooseAvatar、手机号等能力前，后台声明并在代码里处理用户拒绝；
- **内容安全**：昵称、排行榜展示名走 msgSecCheck；若以后允许上传头像，走 mediaCheckAsync；
- **未成年人**：若走小游戏类目，需要实名、防沉迷、适龄提示；工具类也建议不加支付、不做诱导分享；
- **数据删除**：提供注销账号/删除数据入口（个人信息保护法要求）；
- **禁止行为**：诱导分享、虚拟支付绕开、抽奖/红包拉新、无实质内容套壳。

## 7. 提审与发布

1. 微信开发者工具导入项目，填 AppID，真机预览；
2. 上传体验版，添加体验成员自测；
3. 后台提交审核：填写功能页面、测试路径、隐私政策链接、截图；
4. 审核通常 1～7 天；被拒按原因修改后重新提审；
5. 审核通过后发布，可灰度/回滚版本。

常见拒绝原因：类目与实际功能不符、页面空白/死链、隐私政策缺失、诱导分享、测试账号不可用、内容含游戏但类目是工具。

## 8. 时间与费用（估算）

| 项 | 时间/费用 |
|---|---|
| 主体注册 + 认证 | 1～3 个工作日；企业认证约 300 元/年 |
| 域名购买 + 实名 | 1～3 天；30～60 元/年 |
| 域名 ICP 备案 | 7～20 个工作日（免费） |
| 小程序备案 | 平台 1～2 天 + 管局 1～20 个工作日（免费） |
| 后端微信登录改造 | 2～3 天 |
| 小程序前端 | 1～2 周 |
| 提审到上线 | 1～7 天 |
| **合计** | **约 3～5 周**（备案可与开发并行） |

不含：小游戏版号（如走 IAP，周期按月计、费用高）、短信费用、微信支付商户号。

## 10. 需要你先确认的 5 件事

1. **个人主体还是企业主体？**（决定能不能用手机号、支付、web-view）
2. **走小程序（工具/教育）还是小游戏？**（决定要不要版号/游戏备案）
3. **有没有已注册的小程序 AppID？** 有没有已备案域名？
4. **登录方式**：只微信静默登录，还是微信 + 手机号，还是保留用户名密码？
5. **变现**：首版是否完全免费（建议免费，先过审）？

## 11. 推荐落地顺序

1. 先定主体、注册小程序、启动域名 ICP 备案（最耗时，先排队）；
2. 后端加微信登录 + 令牌 Header 模式（不影响现有 Web）；
3. 小程序前端先做“首页 + 作答 + 结算”，排行榜复用现有接口；
4. 补隐私政策、内容安全、账号注销；
5. 小程序备案通过后提审，先发免费版；
6. 上线稳定后再评估手机号登录、支付、小游戏。
