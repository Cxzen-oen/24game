# 上云部署手册（2 核 2G 小规模测试版）

> 实际服务器 121.43.236.209 没有 Docker，已按原生 systemd 方式部署，见 **docs/服务器部署记录-121.43.236.209.md**；本手册的 Docker 方案适用于以后的新服务器。
>
> 目标：一台 Linux 云服务器（2 vCPU / 2 GB），Docker Compose 起 Caddy + Spring Boot + PostgreSQL，先跑通小规模测试。
> 架构与取舍见 **docs/账号与排行榜_上云架构方案.md**；小程序路线见 **docs/微信小程序上线准备清单.md**。

## 0. 2C2G 能跑吗？

能，但要把内存算清楚，并且**不要在服务器上构建前端/后端**：

| 组件 | 内存预算 |
|---|---|
| 系统 + Docker | 300～400 MB |
| Spring Boot（-Xmx512m + Metaspace） | 800～950 MB |
| PostgreSQL（shared_buffers 128MB，连接 40） | 450～600 MB |
| Caddy | 30～60 MB |
| 合计 | 约 1.6～1.9 GB |

再配 **2 GB swap** 兜底。小规模测试（几十个同时在线、几百 DAU）足够；正式放量再升 4G。

关键改动：**本地构建 jar → 上传 → 服务器只做很轻的运行时镜像**，避免 2G 机器跑 Maven + Node 被 OOM Killer 杀掉。项目已提供：

- **deploy/build-local.ps1**（Windows）/ **deploy/build-local.sh**：本地构建可部署 jar；
- **deploy/Dockerfile.runtime**：只拷 jar 的运行时镜像；
- **deploy/server-init.sh**：2G swap、Docker、fail2ban；
- **compose.prod.yaml**：已按 2C2G 调好 JVM、Postgres、容器内存上限。

## 1. 需要准备

| 项 | 说明 |
|---|---|
| 服务器 | Ubuntu 22.04/24.04，2 vCPU / 2 GB / 40 GB+，公网 IP |
| 登录方式 | SSH 密钥（推荐）或 root 密码 |
| 权限 | 需要 root 或 sudo；需要能装 Docker |
| 域名 | 可选。只有 IP 时走 http://IP 调试；HTTPS 需要域名 |
| 本地环境 | Windows PowerShell，已装 Node、Java 21、ssh、scp、tar |

> 如果“互选平台”只给面板（宝塔/PaaS）不给 SSH，或 80/443 已被面板占用，需要换部署方式；先把面板类型和端口占用告诉我。

## 2. 初始化服务器

~~~bash
ssh root@IP

# 系统更新
apt update && apt upgrade -y

# 2G swap + Docker + fail2ban（默认不动防火墙）
# 先把代码上传到 /opt/game24（第 3 节），再执行：
bash /opt/game24/deploy/server-init.sh

# 需要 ufw 时再加 --firewall（只放行当前 SSH 端口 + 80/443）
# bash /opt/game24/deploy/server-init.sh --firewall
~~~

创建部署用户（不要日常用 root）：

~~~bash
adduser --disabled-password --gecos "" deploy
usermod -aG sudo deploy
usermod -aG docker deploy
mkdir -p /home/deploy/.ssh
cp ~/.ssh/authorized_keys /home/deploy/.ssh/authorized_keys
chown -R deploy:deploy /home/deploy/.ssh
chmod 700 /home/deploy/.ssh
chmod 600 /home/deploy/.ssh/authorized_keys
~~~

> 云厂商安全组放行 22 + 80 + 443；不要放行 5432/8080。

## 3. 本地构建并上传

### 3.1 构建 jar（重要）

在本地仓库根目录执行：

~~~powershell
cd D:\24game
powershell -ExecutionPolicy Bypass -File deploy\build-local.ps1
~~~

脚本会：构建前端 → 把 dist 打进 Spring Boot → Maven 打包 → 产出 **deploy/build/game24-demo.jar**。

- 如果本机 8080 还跑着旧后端，先停掉，否则 target/game24-demo.jar 被占用会打包失败；
- 如果改了前端依赖，先删 demo/web/node_modules 再跑，脚本会自动 npm ci。

### 3.2 打包上传

~~~powershell
tar -czf game24-deploy.tar.gz --exclude=node_modules --exclude=target --exclude=dist --exclude=.m2repo --exclude=.git --exclude=backups --exclude=demo/server/src/main/resources/static Dockerfile .dockerignore compose.prod.yaml deploy demo docs .env.prod.example .env.example

scp game24-deploy.tar.gz deploy@IP:/tmp/
~~~

服务器上：

~~~bash
sudo mkdir -p /opt/game24
sudo chown deploy:deploy /opt/game24
tar -xzf /tmp/game24-deploy.tar.gz -C /opt/game24
cd /opt/game24
ls -lh deploy/build/game24-demo.jar   # 确认 jar 已上传
~~~

## 4. 配置生产环境变量

~~~bash
cd /opt/game24
cp .env.prod.example .env.prod
chmod 600 .env.prod

openssl rand -hex 24   # POSTGRES_PASSWORD
openssl rand -hex 32   # JWT_SECRET
~~~

**.env.prod 关键项：**

~~~ini
POSTGRES_DB=game24
POSTGRES_USER=game24
POSTGRES_PASSWORD=<24 字节随机>
JWT_SECRET=<32 字节以上随机>
DOMAIN=<域名或服务器公网 IP>
COOKIE_SECURE=true
APP_TAG=1.0.0
APP_DOCKERFILE=deploy/Dockerfile.runtime
APP_MEM_LIMIT=900m
DB_MEM_LIMIT=640m
PROXY_MEM_LIMIT=96m
~~~

- **只有 IP**：执行 **cp deploy/Caddyfile.ip deploy/Caddyfile**，COOKIE_SECURE=false，DOMAIN 可填 IP；
- **有域名并已解析**：保持默认 Caddyfile 和 COOKIE_SECURE=true。

## 5. 域名解析（有域名时）

域名控制台加 A 记录：game24.example.com → 服务器公网 IP。
解析生效后再启动，否则 Caddy 签证书会失败。大陆服务器用域名开 80/443 通常需要 ICP 备案。

## 6. 首次部署

~~~bash
cd /opt/game24
chmod +x deploy/*.sh
./deploy/deploy.sh
~~~

2C2G 用 runtime 镜像，构建只要几十秒到 1 分钟；看到 app、db、proxy 都是 Up (healthy) 即成功。

~~~bash
docker compose --env-file .env.prod -f compose.prod.yaml ps
curl -fsS http://127.0.0.1/api/health
# {"status":"UP","db":"UP",...}
docker stats --no-stream    # 看三个容器实际内存
~~~

如果只有 IP：打开 **http://IP**；有域名：打开 **https://域名**。

## 9. 更新发布与回滚

更新：

1. 本地重新执行 **deploy/build-local.ps1**；
2. 重新打 tar、上传、解压；
3. 服务器执行 **./deploy/deploy.sh**（自带发布前备份）。

回滚应用：

~~~bash
cd /opt/game24
APP_TAG=0.9.0 docker compose --env-file .env.prod -f compose.prod.yaml up -d --no-build app
~~~

> 数据库迁移是向前的，破坏性变更只能靠备份恢复。

## 10. 2C2G 运维要点

~~~bash
free -m
swapon --show
docker stats --no-stream
dmesg -T | tail -30     # 看有没有 OOM Killer
~~~

- 内存吃紧：把 app 的 JAVA_TOOL_OPTIONS 改成 -Xmx448m（.env.prod 里加一行），或在 compose 里调低；
- 构建时 OOM：不要在服务器跑全量 Dockerfile，继续用 runtime 镜像 + 本地构建；
- 数据库慢：2G 下 shared_buffers 只有 128MB，属正常；榜单查询仍走索引；
- 磁盘：日志已限制 5～10MB × 3，备份保留 14 天，40GB 够小规模测试。

**小规模测试预期**：几十个同时在线、几百 DAU 没问题；如果 CPU 长期 >70% 或内存频繁触发 swap，再升 2C4G。

## 11. 故障排查

| 现象 | 排查 |
|---|---|
| 502 Bad Gateway | docker compose ps 看 app 是否 healthy；logs app 看启动异常（JWT_SECRET 太短、数据库连不上） |
| 容器反复重启 | docker stats / dmesg 看是否 OOM；调低 Xmx 或加 swap |
| 打不开 80/443 | 安全组、ufw、面板是否占用端口；Caddy 日志 |
| 登录后刷新变游客 | COOKIE_SECURE=true 但访问的是 http，改成 false 或配 HTTPS |
| 备份 0 字节 | 看 /var/log/game24-backup.log，pg_dump 是否失败 |
| 磁盘满 | docker system df；清理旧镜像与 backups |
